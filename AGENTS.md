# Action Leopard — project guide

Next.js App Router app for **spatial control of AI-generated action video**: translate real location photos into malleable scenes on a tldraw canvas, produce control frames (A/B pairs), and generate video that respects placement, motion and proportion. Audience: professional filmmakers. Won the competition it was built for; now a real product.

## Commands

- `pnpm dev -p 3001` — dev server (env expects port **3001**)
- `pnpm build` — production build + typecheck (this is the verification gate; no test suite)
- DB migrations: files in `supabase/migrations/`, applied via a throwaway Node `pg` script against `POSTGRES_URL_NON_POOLING` from `.env.local` (no supabase CLI installed). All 4 migrations are applied to the live DB.

## Stack & keys

- Supabase (Postgres+Auth, new-style `sb_publishable_`/`sb_secret_` keys — legacy anon/service-role NOT used), Vercel Blob (all media; client uploads via `/api/blob/upload`), fal.ai (image/video/segmentation), xAI API direct (`grok-4.5` — exact model id) for planner/prompt-writing LLM work, Anthropic API (`claude-sonnet-5` via `@anthropic-ai/sdk`, `src/lib/anthropic.ts`) for the scene judge + fix rewriter (independent model from the builder; structured outputs for verdict JSON; falls back to grok without `ANTHROPIC_API_KEY`).
- All keys in `.env.local` (gitignored). **fal credits are LIMITED** — never generate media in testing without asking; cheap LLM smoke tests are fine.
- Supabase email confirmation is disabled (no SMTP); signup logs straight in. `/auth/confirm` handles both `?code=` and `token_hash` flows for when it's re-enabled.

## Model registry (`src/lib/models.ts`)

- Image: `nano-banana-pro` (`fal-ai/gemini-3-pro-image-preview/edit`), `nano-banana-2` (`fal-ai/nano-banana-2/edit`).
- Video: Grok Imagine 1.5 @ 480/720/1080p (`xai/grok-imagine-video/v1.5/image-to-video`); `kling-3-pro` (`fal-ai/kling-video/v3/pro/image-to-video`, start+end frames); `kling-3-pro-motion` (guide video); `seedance-2` (`bytedance/seedance-2.0/image-to-video`, start+end); `seedance-2-fast` (`bytedance/seedance-2.0/fast/reference-to-video`, up to 9 ref images + 3 guide videos, refs addressed as `@Image1`/`@Video1` in the prompt).
- Segmentation: `fal-ai/sam-3-1/image` (text + point + box prompts, per-instance masks). Also available: `fal-ai/sam-3/3d-objects` (image+masks → per-object GLB/gaussian splats + camera pose) — earmarked for the future 360° shot-framing stage.
- fal endpoint prefixes vary (`fal-ai/...`, `bytedance/...`, `xai/...`). Verify any new endpoint via `https://fal.ai/api/openapi/queue/openapi.json?endpoint_id=<id>` BEFORE writing integration code.

## Architecture map

- `src/lib/prompts.ts` — ALL system prompts: director voice, screen-space directing rules, frame A→B delta strategy with proportion discipline (never "larger in frame"; anchor scale to environment), art-direction-images-are-style-only rules, scene translation (+ outline addendum, structural-elements rules), agent prompt. This file is the product's soul; edit deliberately. In-prompt examples use GENERIC subjects (sedan/coupe/pickup, river/rock wall, tunnel) on purpose — never let them drift back to matching a specific test project's vehicles or landmarks.
- `src/lib/generate.ts` — server: fal calls per model family → copy output to Blob (`copyToBlob`) → insert `assets` row.
- `src/lib/canvas.ts` — client tldraw helpers: `sceneToCanvas` (blocks/outlines), `cutoutsToCanvas` (movable PNG pieces), scale legend, canvas→PNG export, `saveBlobAsAsset` (upload + asset row), `uploadBlobOnly` (upload only — cutout pieces), annotate-background, clear. tldraw v5 draw shapes need `compressLegacySegments` from `@tldraw/tlschema` (direct dep, pinned to tldraw's version).
- `src/lib/segment.ts` — client mask processing: `traceMask`, `cutoutFromMask` (distance-field feather), `cutoutsFromAtlas` (color-key stickers), sticker/plate packaging helpers.
- API routes: `scene/translate` (grok vision → JSON blocking diagram + scale_anchors; mode blocks|outlines), `scene/segment` (SAM 3.1 text+box+point, cap 24, concurrency 4), `scene/world` (plate = empty location via image edit; atlas = flat color instance map), `prompt/write` (modes image-a/image-b/video; cites scale anchors), `generate/image|video`, `agent` (SSE tool loop: translate_scene, generate_image, generate_video, list_assets), `assets/delete` (Blob del + row), `blob/upload`.
- UI: `Workspace.tsx` orchestrates. `CanvasPanel` (scene-mode cutouts/traced/outlines/blocks; cutouts quality Cinematic|Fast; ✦ Scene from image, Save shot, Clear), `PreviewPanel` (viewer + image palette, A/B frame marking, upload outside image, annotate, delete), `PromptBar` (Frame A/B/Video tabs → `projects.prompts` jsonb, input chips include/exclude), `VideoStrip` (click=preview, dblclick=modal player z-200), `SidePanel` (intent, reference, art direction text+thumbs, elements, agent launcher), `AgentModal` (SSE chat; applies translate_scene results to canvas), `TopBar` (hamburger: projects/assets/+new project; model selects; theme icon), `/studio/assets` page (all assets, filters, viewer, copy URL/download/delete).
- State: zustand (`src/lib/store.ts`). Theme: `.dark` class + localStorage `al-theme`; tldraw follows via MutationObserver; canvas wrapper is `isolate z-0` so modals stay above tldraw's internal z-indexes.
- DB (all RLS `auth.uid() = user_id`): `projects` (intent, art_direction, reference_image_url, canvas_snapshot jsonb, prompts jsonb {image_a,image_b,video}, scene_meta jsonb {summary, scale_anchors}, image_model, video_model, **project_type shot|scene, script, location_map jsonb**), `elements` (kind/name/notes/image_url), `assets` (type: image|video|canvas-shot|drawing|reference|art-direction; sort_order drives the sequence strip; scene versions tagged `metadata.shot_id/shot_role/version`), `shots` (kind shot|transition, sort_order, spec jsonb ShotSpec, prompts jsonb, status planned→approved→generating→judging→fixing→passed|escalated|accepted, revision_count, judge jsonb verdicts, start/end/video_asset_id), `agent_messages` (unused so far).

## Scene projects ("Create a scene" — agentic planner + self-correcting loop)

Second project type chosen at "+ New project" (`projects.project_type`, default `shot`; single-shot path untouched). User supplies script + ordered **location map** (SidePanel) → Builder/Judge/Manager loop, **client-orchestrated** (`src/lib/scene-agent.ts`) because fal.subscribe blocks serverless fns; every transition persists to `shots` so refresh resumes (`computeResume`; interrupted generations reconciled by `metadata.version`).

- **Builder**: `/api/scene/plan` (SCENE_PLAN_SYSTEM + ACTION_DIRECTIVES car/foot/fight/boat/aircraft/space) — one grok vision call over labeled location images → one-beat shots with ShotSpec; continuity is WORLD-STATE only (exit_continuity of k = entry_continuity of k+1), camera varies freely per shot for rhythm; `planScene()` inserts rows, replaces un-generated plan rows. The plan also emits **scene invariants** (2-5 premise facts: who chases whom → who is ahead, pack travel direction) persisted to `projects.scene_meta.invariants` and fed to every judge + fix call; specs must state deliberate exceptions (overshoots) explicitly.
- **Judge**: `/api/scene/judge` — one frame per call vs ground truth (location ref, prev approved frame, spec + script_excerpt, anchors, scene invariants); seven checks (location-fidelity, scale-proportion, screen-direction, continuity-adjacent, anatomy, script-intent — element-by-element against the script excerpt (each vehicle's lane, posture, maneuver phase, effect), art-direction); a fail with zero failed checks counts as pass (never burns credits). Parse robustness: `reviewChat` throws on `max_tokens` truncation (thinking counts against the budget — judge/fix run at 16384), route retries ×3, then returns a verdict flagged `unparseable: true` — the run loop RE-JUDGES (2×, free) instead of burning a generation + fix, then escalates without spending.
- **Manager**: `runScene()` strictly sequential in sort order — each shot generates → judges → fixes (`/api/scene/fix` rewrites full frame-A prompt) until pass, hard cap `MAX_AUTO_FIXES = 2` then `escalated` (canvas-blocking verdicts NO LONGER escalate immediately — the fixer rewrites the geometry paragraph instead; only the cap escalates); continuity input is always the predecessor's judge-approved frame. Escalation is a light choice: the card shows every generated version as a clickable thumbnail (`approveShotFrame` — approves that version, judge may have discarded a good one), Upload frame (`uploadShotStartFrame`), Retry, Shot detail. Marking a Start frame in shot detail on an escalated/planned shot ALSO approves it (`shot-scope` setStart → status accepted). Shot cards have hover ✓ (approve escalated) and ▶ (`makeVideos({shotIds})` — single-shot clip); the footer offers "Generate N videos" directly, with end frames a de-emphasized "(optional)" (only for start+end models — never push it as the required next step). Agent-loop generations call `addAssets(…, {select:false})` and scoped PreviewPanel only honors selections in the shot's own asset set — the agent must NEVER hijack what the user is viewing; opening shot detail clears the selection so the shot's start frame/latest version shows. Approval gate before any generation ("Generate N start frames"); auto-loop covers start frames; `makeEndFrames()` (confirm-gated) writes+generates frame B for passed/accepted shots; `makeVideos()` (confirm-gated) fills clips. `cancelRun()` cooperatively stops after the in-flight step (progress persisted, Resume continues); `replanScene()` deletes all shots and re-plans from the same inputs. Dev-only dry-run exercises the whole loop with no fal spend.
- **Spatial discipline**: the CAMERA GEOMETRY CONTRACT (in SCREEN_SPACE_RULES) requires every image prompt to derive camera position → per-subject visible faces (taillights/headlights/profile) → per-landmark frame edges, stated twice (image models bias toward front views); reversing the camera mirrors the whole chain. HEADING-NOT-LANE rule: a vehicle's visible face comes from travel direction, never lane — wrong-way-lane subjects traveling with the pack must be prompted "in the oncoming lane but traveling the SAME direction, taillights to camera" (image models otherwise draw grilles on anything in the left lane). Planner enforces orientation discipline (pursued never faces pursuer), camera variety by vicinity extrapolation, landmark non-repetition WITH bookkeeping (entry_continuity names passed landmarks; prompts beyond a landmark carry an explicit "does NOT appear" negative), engagement distance. Judge observes-first (verdict `observed` field — per-vehicle face AND implied travel direction), checks per-vehicle heading, pursuit order vs invariants, landmark progression, lane-width proportion, stray objects in the travel path, imminent-collision sanity, tolerates legitimate mid-pass order, and may only fail on cited observations. Fix rewriter starts from the judge's `observed` text and writes explicit counter-instructions.
- **UI**: SHOTS|SHOT-DETAIL tabs in Workspace (internal view key still `fixit`); the shots-canvas toolbar (Action scene maker/Upload/Add shot/zoom) portals into the centered slot (`#scene-toolbar-slot`) of the tab row — nothing floats over the canvas; ⤓ Export sits on the tab row's far right (`src/lib/export.ts`, jszip: zip of inputs/ locations+elements+reference+art-direction, shots/shot-NN/ role-vN frames+clips, generated/, plus prompts.md with script, invariants, specs, and every prompt). PromptBar's INPUTS row is the single inputs surface: one horizontal-scroll line (never wraps/resizes), thumbnail chips; scoped to a shot it shows the EXACT agent-loop generator inputs with specific labels (location — {label}, prev shot frame, element — kind: name, art direction N) via `shotGenerationInputs`. `ShotsCanvas` (custom pan/zoom grid, NOT tldraw; numbered 16:9 cards, dbl-click opens shot detail scoped to the shot, hover "+" between cards inserts a transition using prev end frame + next start frame; card images drag to desktop + ⤓ download). `SceneAgentPanel` ("Action scene maker": dockable/floating/resizable/minimizable window with localStorage layout — drag header to release from dock, minimize to a movable chip; closing while running leaves a progress chip so runs are never hidden; intake with intent+script textareas + ✦ Plan scene, plan review, live feed, escalation cards, Cancel run/Resume/end-frames/Re-plan footer). ✦ Plan scene also sits under the Script box in SidePanel. Scene state in `src/lib/scene-store.ts` (separate zustand store).
- **Projects**: hamburger drawer lists non-archived projects for quick switching (hover Arch to archive); studio page has an Archived toggle + per-row Duplicate (copies inputs — intent/script/art direction/models/elements/reference+art-direction asset rows/location map — into a fresh project, no shots/media) / Archive / Delete. Migration 00006 adds `projects.archived`.
- **Shot scoping**: `src/lib/shot-scope.ts` `useShotScope()` — PromptBar/PreviewPanel read prompts/A-B frames/reference/palette/anchors through it; unscoped returns exactly the old project-backed values; scoped persists to the shot row and tags generations, so version revert = select old frame + press Start frame. Fix-it stack stays mounted-but-hidden across tab flips (tldraw editor must not remount).

## UI style rules (user is strict)

Minimalist black/white, fine 1px borders, sharp corners (global CSS kills border-radius except inside tldraw), Geist sans + Geist Mono accents, NO blue/purple UI, red/green only when semantically necessary, light+dark modes, no clutter.

## Working preferences

- The prompt-writing quality (screen-space directing, proportion discipline, no embellishment, no imposed golden hour, art direction as law) is the core differentiator — protect it.
